# camellia128_epsiron 使い方ガイド

`camellia128_epsiron` モジュールのポート一覧と、鍵設定・暗号化・復号の操作手順を波形付きで説明する。

## 1. 概要

- Camellia-128(鍵長・ブロック長ともに128bit)の暗号化・復号を行うコア。
- データ・鍵ともに **8bitバイトシリアル** で入出力する(ピン数を抑え、回路規模を最小化)。
- モード(ECB/CBC等)は持たず、1ブロック(16バイト)の暗号化/復号のみを行う。
- 外部とのやり取りはすべて **valid/ready ハンドシェイク**。

## 2. ポート一覧

| 信号 | 方向 | 幅 | 説明 |
|---|---|---|---|
| `clk` | in | 1 | クロック |
| `rst` | in | 1 | 同期リセット(High アクティブ) |
| `cmd_valid` | in | 1 | コマンド有効 |
| `cmd_ready` | out | 1 | コマンド受付可(`IDLE` 中のみ1) |
| `cmd_op` | in | 2 | `0`=KEY(鍵設定) `1`=ENC(暗号化) `2`=DEC(復号) `3`=予約(受理するが何もしない) |
| `in_valid` | in | 1 | 入力バイト有効 |
| `in_ready` | out | 1 | 入力受付可(鍵/平文/暗号文を受け取れる間1) |
| `in_data` | in | 8 | 入力バイト(鍵バイト、または平文/暗号文バイト) |
| `out_valid` | out | 1 | 出力バイト有効 |
| `out_ready` | in | 1 | 出力受取可 |
| `out_data` | out | 8 | 出力バイト(暗号文/平文) |
| `busy` | out | 1 | `IDLE` 以外の間1(コマンド処理中) |
| `key_valid` | out | 1 | 鍵設定が完了していると1。`rst` で0に戻る |

ポートはすべて1モジュールに閉じている(サブモジュールへのパラメータ等はなし。外部ファイル・`` `include`` にも依存しない)。

## 3. 基本ルール

- **バイト順は MSBファースト。** 最初に送受信するバイトが128bit値の `bit[127:120]`。
- **ハンドシェイク**:信号 `X_valid` と `X_ready` が両方1のサイクルで転送が成立する(標準的な valid/ready プロトコル)。
- 片方しか1でない間は何も進行しない(ストール)。送信側は `valid` を保持し、受信側は `ready` を保持すればよい。
- `cmd_valid`・`in_valid`・`out_ready` のいずれも、相手の `ready`/`valid` を待たずに好きなタイミングで上げ下げしてよい。コアが `IDLE` でなければ `cmd_ready` は常に0。

### 3.1 ハンドシェイクの波形(1バイト転送の例)

`in_valid`/`in_ready` を例にする(`cmd_valid`/`cmd_ready`、`out_valid`/`out_ready` も同じ形)。
受信側(コア)が2サイクル分`in_ready=0`でストールさせてから受け取る例:

```
cycle    :   0    1    2    3    4
clk      : ‾‾\__/‾‾\__/‾‾\__/‾‾\__/‾‾\__
in_valid : ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\______   (送信側がずっと1を保持)
in_ready : ____________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   (受信側は2サイクル待ってから1)
in_data  :   D0   D0   D0   --   --   --
                         ^
                 cycle2: valid=1 & ready=1 → この立ち上がりエッジで D0 が転送される
```

- `in_valid=1` かつ `in_ready=0` の間、`in_data` の値は保持しておく(転送が成立するまで変えない)。
- 転送が成立した**次のサイクル**で送信側は次のバイトに進める(valid を下げる/次データに替える)。

## 4. 鍵設定(KEYコマンド)

### 4.1 手順

1. `cmd_valid=1`、`cmd_op=0`(KEY)にしてコマンドを送る。`cmd_ready=1`(=IDLE中)のサイクルで受理される。
2. 受理後、`busy=1` になり `in_ready=1` が立つ。鍵16バイトを **MSBファースト** で `in_data`/`in_valid` に送る。
3. 16バイト送り終えると、コア内部でKA(拡張鍵)を生成し、自動的に `IDLE` に戻る(`busy=0`)。このとき `key_valid=1` になる。
4. 出力(`out_data`)は発生しない。

ストールなしの場合、コマンド受理の次のサイクルから数えて **80サイクル** で完了する(鍵16バイト入力 + 内部処理)。

### 4.2 波形(ストールなし、鍵 `0123456789ABCDEF...` の例)

```
cycle     :   0     1     2     3    ...   16    17    ...    80    81
clk       : ‾‾\_ /‾‾\_ /‾‾\_ /‾‾\_ ... /‾‾\_ /‾‾\_ ...  /‾‾\_ /‾‾\_
cmd_valid : __/‾‾\________________ ... ____________ ...  ____________
cmd_ready : ‾‾‾‾‾‾\______________ ... ____________ ...  ____/‾‾‾‾‾‾‾
cmd_op    :    KEY  -    -    -   ...    -     -    ...   -      -
in_valid  : ________/‾‾‾‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾\_______ ...  ____________
in_ready  : ________/‾‾‾‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾\_______ ...  ____________
in_data   :    --   -  01   23   45  ...  10   --  ...   --     --
busy      : ________/‾‾‾‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾‾‾‾‾‾‾‾‾ ...  ‾‾‾‾\______
key_valid : ________________________ ... ____________ ...  ____/‾‾‾‾‾
```

- cycle0: コマンド受理(`cmd_valid & cmd_ready`)。
- cycle1〜16: 鍵16バイトを `in_data` に送る(1バイト/サイクル、ストールなし)。
- cycle17〜80: コア内部処理(FRND/KXOR/KSTORE)。外部とのやり取りは発生しない。`in_valid`/`out_ready` を見ない。
- cycle80で `IDLE` に戻り、`key_valid=1`。

### 4.3 データ表(最初の数バイトのみ)

| cycle | `in_data` | 意味 |
|---|---|---|
| 1 | `0x01` | 鍵バイト0(MSB) |
| 2 | `0x23` | 鍵バイト1 |
| 3 | `0x45` | 鍵バイト2 |
| … | … | … |
| 16 | `0x10` | 鍵バイト15(LSB) |

## 5. 暗号化・復号(ENC/DECコマンド)

### 5.1 手順

1. **事前に鍵設定済み**(`key_valid=1`)であること。未設定でENC/DECを実行すると結果は不定(エラーにはならない)。
2. `cmd_valid=1`、`cmd_op=1`(ENC)または`2`(DEC)で送る。
3. 平文(ENC時)または暗号文(DEC時)16バイトを `in_data`/`in_valid` に送る。
4. コアが処理し、結果16バイトを `out_data`/`out_valid` に出力する。`out_ready=1`のサイクルで受け取る。
5. 16バイト出力後、自動的に `IDLE` に戻る。

ストールなしの場合、コマンド受理の次のサイクルから数えて **212サイクル** で完了する(入力16 + 内部処理176 + 出力16)。
鍵を変更しない限り、鍵設定し直さずに ENC/DEC を何度でも連続実行できる。

### 5.2 波形(ストールなし、ENCの例・抜粋)

```
cycle      :   0    1   ...   16   17  ...  196  197  ...  212  213
clk        : ‾‾\_ /‾‾\_ ... /‾‾\_ /‾‾\_ ... /‾‾\_ /‾‾\_ ... /‾‾\_ /‾‾\_
cmd_valid  : __/‾‾\___ ... __________ ... __________ ... ____________
cmd_op     :    ENC -  ...    -    -  ...    -    -  ...    -     -
in_valid   : ______/‾‾ ... ‾‾\______ ... __________ ... ____________
in_data    :   --   PT0 ...  PT15 -- ...   --   -- ...   --    --
out_ready  : ‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾‾‾‾‾‾ ... ___/‾‾‾‾‾ ... ‾‾‾‾‾‾‾‾‾‾‾‾
out_valid  : _________ ... _________ ... __________/‾‾ ... ‾‾\______
out_data   :   --   -- ...   --   -- ...   --   --  CT0 ...  CT15  --
busy       : __/‾‾‾‾‾‾ ... ‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾‾‾‾‾‾‾ ... ‾‾‾‾\______
```

- cycle0: コマンド受理。
- cycle1〜16: 平文16バイトを入力(`PT0`=平文バイト0 … `PT15`=平文バイト15)。
- cycle17〜196: コア内部処理(ラウンド処理・FL/FL⁻¹)。
- cycle197〜212: 暗号文16バイトを出力(`CT0`…`CT15`)。
- cycle212で `IDLE` に戻る。

DECの場合は `cmd_op=2`、`in_data` に暗号文、`out_data` に平文が出力される点以外は同じ波形。

## 6. ストール(入力待ち・出力待ち)

`in_valid=0` の間、または `out_ready=0` の間は、内部状態(状態レジスタ・鍵・カウンタ等)はすべて保持される。処理を止めたまま好きなだけ待ってよい。

```
cycle     :   5    6    7    8    9   10
in_valid  : ‾‾‾‾\______________/‾‾‾‾‾‾
in_ready  : ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   (LOAD中は常に1)
in_data   :   D3   D3   D3   D3   D4   D4
                                 ^
                    cycle9: valid=1 & ready=1 で D4 が転送される
```

上の例では cycle6〜8 の3サイクル、送信側が `in_valid=0` にしてストールしている。コア側は何も進めず、再開(cycle9)してから続きの転送が成立する。

## 7. busy 中のコマンド拒否

`busy=1`(処理中)の間は `cmd_ready=0` になり、`cmd_valid` を上げても無視される(受理されず、現在の処理が壊れることもない)。

```
cycle      :   10    11    12    13
busy       : ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   (処理中)
cmd_valid  : ____/‾‾‾‾\____________   (試しにコマンドを出してみる)
cmd_ready  : ____________________   (0のまま。受理されない)
```

新しいコマンドを受理させたい場合は、現在の処理が完了して `busy=0`(`cmd_ready=1`)になるまで待つ必要がある。

## 8. リセット

`rst=1` のサイクルの次のクロックエッジで `IDLE` に戻り、`key_valid=0` になる。処理の途中でリセットしても安全に中断できる。

```
cycle      :   50    51    52    53
busy       : ‾‾‾‾‾‾‾‾\_______________   (処理中にrstを入れる)
rst        : ______/‾‾‾‾\_____________
key_valid  : ‾‾‾‾‾‾‾‾\_______________   (0に落ちる)
```

リセット後は鍵設定(KEYコマンド)からやり直す。

## 9. サイクル数まとめ

| コマンド | サイクル数(ストールなし、コマンド受理サイクルを除く) |
|---|---|
| KEY | 80 |
| ENC / DEC | 212 |

ストールが入ると、ストールしたサイクル数だけ単純に延びる(処理は保持されるだけで、やり直しにはならない)。

## 10. 最小限の使用例(擬似コード)

```
// 1. 鍵設定
cmd_op = KEY; cmd_valid = 1;
wait until cmd_ready;                 // IDLE中であること
cmd_valid = 0;
for i in 0..15:
    in_data = key_byte[i]; in_valid = 1;
    wait until in_ready;              // LOAD中は常に1
    in_valid = 0;
wait until key_valid;                 // 内部処理完了(自動でIDLEに戻る)

// 2. 暗号化
cmd_op = ENC; cmd_valid = 1;
wait until cmd_ready;
cmd_valid = 0;
for i in 0..15:
    in_data = plaintext_byte[i]; in_valid = 1;
    wait until in_ready;
    in_valid = 0;
for i in 0..15:
    out_ready = 1;
    wait until out_valid;
    ciphertext_byte[i] = out_data;
    out_ready = 0;
```

実際のテストベンチでの実装例は [`../sim/tb_camellia128_epsiron.v`](../sim/tb_camellia128_epsiron.v) の `send_cmd`/`send_byte`/`recv_byte` タスクを参照。
